# Dashboard ยอดขายรายสาขา

**เปิดใช้งานได้เลยที่ → https://senpa1-x.github.io/branch-sales-dashboard/**

Dashboard อ่านข้อมูลจาก Google Sheet ของคุณเอง แล้ว **แปลง Product เป็น Category ให้อัตโนมัติ**
ไฟล์ HTML ไฟล์เดียวจบ ไม่ต้องติดตั้งอะไร ไม่มี backend

> 🔒 **โค้ดนี้ไม่มีข้อมูลของใครอยู่เลย** — ไม่มีรหัสสาขา ไม่มีลิงก์ Sheet
> ครั้งแรกที่เปิดจะมีหน้าให้กรอกเอง แล้วเก็บไว้ใน `localStorage` ของเบราว์เซอร์เครื่องนั้น
> ไม่ถูกส่งขึ้นเซิร์ฟเวอร์ใดๆ · คนอื่นที่เปิดลิงก์เดียวกันจะเห็นแค่หน้ากรอกค่า ไม่เห็นข้อมูลของคุณ

## 🚀 เริ่มใช้งาน

เปิดหน้าเว็บ → กรอก 3 อย่าง → เสร็จ

1. **รหัสสาขา** — ใช้แสดงบนหัวเท่านั้น
2. **ชื่อ AM** — ไม่ใส่ก็ได้
3. **Google Sheet รายปี** — ใส่ปี ค.ศ. 2 หลัก (เช่น `26`) + วางลิงก์ Sheet เต็มๆ ได้เลย ระบบดึงรหัสออกมาเอง

กดปุ่ม **+ เพิ่มปี** ถ้ามีหลายปี · แก้ทีหลังได้ที่ลิงก์ **ตั้งค่าแหล่งข้อมูล** ท้ายหน้า

Sheet ต้องตั้งเป็น **"ทุกคนที่มีลิงก์ • ผู้อ่าน"** ระบบถึงจะอ่านได้

### เปิดจากเครื่องตัวเอง

```bash
python3 -m http.server 8000
```

แล้วเข้า `http://localhost:8000`

> **ทำไมต้องผ่านเซิร์ฟเวอร์?** ถ้าดับเบิลคลิกเปิดไฟล์ตรงๆ (`file://`) เบราว์เซอร์บางตัวจะบล็อก
> การอ่านข้อมูลข้ามโดเมน หน้าจะขึ้นกล่องแดงพร้อมคำสั่งนี้ให้อยู่แล้ว — ลองเปิดตรงๆ ก่อนได้
> ถ้าใช้ได้ก็ไม่ต้องรันเซิร์ฟเวอร์

## 🔐 แบบมีรหัสผ่าน (Cloudflare Worker)

ถ้าไม่อยากกรอก Sheet ID ซ้ำทุกเบราว์เซอร์ และอยากล็อกไม่ให้คนนอกเข้าถึง
ให้ deploy เป็น Cloudflare Worker แทน — โฟลเดอร์ `worker/`

```
เปิด URL → ใส่รหัสผ่านครั้งเดียว (จำไว้ 30 วัน) → เห็นข้อมูลเลย ไม่มีหน้าตั้งค่า
```

Worker จะเช็ครหัสก่อน แล้วค่อยส่งหน้า dashboard พร้อม**ฝังค่า config มาให้เสร็จ**
คนที่ยังไม่ผ่านรหัสจะไม่ได้ไฟล์ dashboard เลย — ได้แค่หน้าใส่รหัส

### วิธี deploy

```bash
npx wrangler login
```

(เปิดเบราว์เซอร์ให้กด Allow — ทำครั้งเดียว) แล้ว

```bash
./worker/deploy.sh
```

สคริปต์จะตั้ง secret ทั้ง 3 ตัวแล้ว deploy ให้เอง

### ค่าลับ 3 ตัว

เก็บเป็น **Worker secret** ไม่ได้อยู่ในโค้ดหรือใน git

| ชื่อ | คืออะไร |
|---|---|
| `DASH_PASSWORD` | รหัสผ่านที่ใช้เข้าเว็บ |
| `COOKIE_SECRET` | กุญแจสุ่มไว้เซ็น cookie (กัน cookie ปลอม) |
| `DASH_CONFIG` | JSON ของรหัสสาขา + Sheet ID ที่จะฝังลงหน้าเว็บ |

ค่าจริงอยู่ในไฟล์ `worker/secrets.local.json` ซึ่ง **ไม่ถูก push** (อยู่ใน `.gitignore`)

### เปลี่ยนรหัสผ่าน / เพิ่มปีใหม่

แก้ `worker/secrets.local.json` แล้วรัน `./worker/deploy.sh` ใหม่

### เร็วขึ้นด้วย cache

บน Worker เบราว์เซอร์**ไม่ต้องคุยกับ Google เลย** — ขอที่ `/api/sheets` ครั้งเดียว
Worker ไปดึงทุกแท็บให้แล้วเก็บ cache ไว้ 10 นาที

| | เบราว์เซอร์ยิงเอง | ผ่าน Worker |
|---|---|---|
| จำนวนคำขอออกนอก | 24 | **1** |
| ขนาดที่โหลด | ~780 KB | **34 KB** (บีบอัดแล้ว) |
| เวลา | 8-12 วิ | **~0.3 วิ** |

กดปุ่ม **⟳ Refresh** = บังคับดึงใหม่จาก Google ข้าม cache (ใช้เวลา ~10 วิ)

### ความปลอดภัยที่ใส่ไว้

- cookie เซ็นด้วย **HMAC-SHA256** แก้เนื้อในไม่ได้ หมดอายุ 30 วัน
- เทียบรหัสผ่านผ่าน SHA-256 แบบ **เวลาคงที่** ไม่ให้เดาทีละตัวจากเวลาตอบกลับ
- ใส่รหัสผิดหน่วง 0.7 วินาที กันไล่เดารัวๆ
- cookie เป็น `HttpOnly` + `Secure` + `SameSite=Lax` — JavaScript อ่านไม่ได้
- หน้าที่มี config ส่งพร้อม `Cache-Control: no-store` ไม่ให้ proxy เก็บไว้

## 🗓️ การแสดงเดือน

หน้าเว็บแสดงเดือนเป็น **ชื่อย่อ + พ.ศ.** เช่น `ก.ค. 2569` · เดือนปฏิทินปัจจุบัน
ต่อท้ายว่า **· กำลังดำเนินอยู่**

ส่วน**คีย์ภายใน**ที่ใช้ค้นข้อมูลยังเป็น ค.ศ. ย่อ (`ก.ค.'26`) ตามที่อ่านมาจากชีต
แยกกันไว้เพื่อให้เปลี่ยนหน้าตาได้โดยไม่กระทบการจับคู่ข้อมูล — แปลงที่ฟังก์ชัน
`pLabel()` กับ `beYear()` จุดเดียว

## 📗 โครงสร้าง Sheet ที่ระบบรองรับ

รองรับ 2 ชุดข้อมูล สลับดูด้วยปุ่ม **💰 ยอดขาย / 🔧 งานซ่อม** (ปุ่มจะโผล่เมื่อใส่ชีตงานซ่อมแล้ว)

### ชีตยอดขาย

**1 ไฟล์ = 1 ปี** · แต่ละแท็บชื่อ `เดือน 1` … `เดือน 12` = 1 เดือน
แต่ละแถวคือสินค้า 1 รายการ (สรุปมาแล้วต่อรหัสสินค้า ไม่ใช่รายบิล)

ระบบไล่หาแท็บ `เดือน 1` ถึง `เดือน 12` ของทุกปีเอง — **เพิ่มแท็บเดือนใหม่แล้วกด Refresh ก็ขึ้นเลย**

### ชีตงานซ่อม GSX

**1 ไฟล์ = 1 ปี** · **แท็บเดียวชื่อ `ชีต1`** ทั้งปี · แต่ละแถวคือ 1 งานซ่อม
ระบบแยกเดือนเองจากคอลัมน์ `Created Date` (รูปแบบ `MM/DD/YY HH:MM AM/PM`)

| คอลัมน์ | ใช้ทำอะไร |
|---|---|
| `Created Date` | แยกเดือน |
| `Repair Type` · `Product Name` · `Customer Reported/Technician Verified Component Issue` · `Repair Classification` · `Part Number` | รวมเป็นข้อความก้อนเดียวเพื่อแยกหมวด |
| `Repair Status` | ตัดงานที่ยกเลิกออก |

หน่วยเป็น **จำนวนงาน** ไม่ใช่บาท · หมวด: ACC · Airpods · CPU · iPad · iPhone Battery · iPhone Display · iPhone Other · Watch

### คอลัมน์ที่ระบบใช้

| คอลัมน์ | ใช้ทำอะไร |
|---|---|
| `ราคาขายนำมาคิดกำไร` | ยอดขาย (แถวที่เป็น 0 จะถูกข้าม) |
| `Category (Name)` · `Sub Category` · `Product (Name)` | ใช้ตัดสินว่าเป็นหมวดไหน |
| `Number` | จำนวนชิ้น |
| `Product (Code)` · `Product (Name)` | ตารางสินค้าขายดี |

คอลัมน์อื่นในไฟล์ไม่ถูกใช้

## 🏷️ กฎแปลง Product → Category

อยู่ที่ฟังก์ชัน `mapCategory()` อ่าน 3 คอลัมน์ (แปลงเป็นตัวพิมพ์ใหญ่ก่อน)
แล้วไล่ตามลำดับ — **ตัวแรกที่เข้าเงื่อนไขชนะ**

**หลักคิด:** ถ้าชื่อสินค้าบอกได้ว่าเป็นชิ้นส่วนอะไรของอุปกรณ์ไหน ให้เชื่อชื่อก่อน
เพราะ Sub Category ในข้อมูลต้นทางใส่ไม่สม่ำเสมอ — จอ iPhone รุ่นเดียวกันบางแถวเป็น
`IPHONE DISPLAY` บางแถวเป็น `IOS-SUR` / `EX-IPHONE` / `APPLE SERVICE`
ชื่อไหนไม่บอกอุปกรณ์ ค่อยตกไปใช้ Sub Category / Category

| # | เงื่อนไข | → หมวด |
|---|---|---|
| 1 | `Category = SERVICE` และ `SubCat = ICARE` | Service Bill |
| 2 | `Category = APPLE SERVICE` และ Product มี `SERVICE FEE` | Exchange — เป็นค่าบริการ ไม่ใช่ค่าอะไหล่ |
| 3 | มี `APPLE CARE` | AC+ |
| 4 | **ชื่อขึ้นต้นด้วย `Display` + มี `IPHONE`** | **iPhone Display** |
| 5 | **ชื่อขึ้นต้นด้วย `Display` แต่ไม่มี `IPHONE`** | **CPU** — เป็นจอ Mac |
| 6 | ชื่อมี `IPHONE` + `BATTERY` | iPhone Battery |
| 7 | `Category = APPLE SERVICE` และ SubCat ไม่ใช่ BATTERY/CPU/ICARE/DISPLAY | Exchange |
| 8 | มี `BATTERY` | iPhone Battery |
| 9 | มี `CPU` | CPU |
| 10 | มี `DISPLAY` | iPhone Display |
| 11 | มี `FILM` | Film |
| 12 | ไม่เข้าข้อไหนเลย | **ACC** |

ข้อ 4-6 ดูจาก**ชื่อสินค้า** ข้อ 7-11 ดูจาก **Sub Category / Category**

> **ทำไม `DISPLAY` ที่ไม่มี `IPHONE` ถึงเป็น CPU:** สแกนข้อมูลจริง 20 เดือนแล้ว
> จอที่ไม่ใช่ iPhone เป็นจอ Mac ทั้งหมด (ชื่อลงท้ายด้วยสี MacBook อย่าง Space Black,
> Starlight, Midnight หรือมี MBA) **ไม่มีจอ iPad / Watch / AirPods ปนเลยสักแถว**

> **ทำไมต้อง "ขึ้นต้นด้วย" ไม่ใช่แค่ "มีคำว่า":** อะไหล่จริงตั้งชื่อแบบ
> `<ชื่อชิ้นส่วน>, <รุ่น/สี>` เช่น `Display, iPhone 17 Pro Max` ส่วนค่าบริการอ่านเป็นประโยค
> เช่น `ACS ISF IPHONE DISPLAY OR BACK GLASS` ซึ่งมีคำว่า DISPLAY แต่ไม่ใช่ตัวจอ
> กฎจึงเช็ค 2 ชั้น — ต้องขึ้นต้นด้วยชื่อชิ้นส่วน (ยอมให้มี `SVC,` นำหน้า) **และ**
> ต้องไม่มี `FEE` / `ISF` / ไม่ขึ้นต้นด้วย `ACS` (ดูฟังก์ชัน `isPartNamed()` กับ `isFeeName()`)

### ตัวอย่างการจับคู่

คู่ `Category (Name)` / `Sub Category` ที่พบบ่อยในข้อมูลศูนย์บริการ Apple และหมวดที่ได้:

```
APPLE SERVICE / IOS BATTERY     → iPhone Battery
APPLE SERVICE / APPLE SERVICE   → Exchange
APPLE SERVICE / IPHONE DISPLAY  → iPhone Display
APPLE SERVICE / CPU             → CPU
APPLE SERVICE / EX-ACC · EX-IPAD · EX-WATCH · IOS-SUR · SPARE PART → Exchange
APPLE CARE    / APP FOR IPHONE · IPAD · MAC · WATCH · HEADPHONES   → AC+
SERVICE       / ICARE           → Service Bill
```

แต่ถ้าชื่อสินค้ามีคำว่า `DISPLAY` กฎข้อ 4-5 จะชนะ Sub Category เสมอ เช่น
`Display, iPhone 17 Pro Max` ที่ Sub เป็น `IOS-SUR` ก็ยังเข้า iPhone Display

ถ้าวันหนึ่งมีสินค้าใหม่ที่ไม่เข้ากฎ ระบบจะ **ขึ้นกล่องเหลืองเตือนพร้อมบอกคู่ Category/SubCategory
ที่ตกหล่น** ให้เอาไปเพิ่มกฎได้ทันที

## 🔧 กฎแยกหมวดงานซ่อม (GSX)

ต่างจากฝั่งยอดขายตรงที่รวม **6 คอลัมน์เป็นข้อความก้อนเดียว** ก่อนแล้วค่อยจับคำ
เพราะชนิดงานอาจอยู่ในช่องอาการเสีย ไม่ใช่แค่ชื่อรุ่น — อยู่ที่ `mapGsx()`

| # | เงื่อนไข | → หมวด |
|---|---|---|
| 1 | มี `SERVICE NON-REPAIR` | **ไม่นับเป็นงานซ่อม** (โชว์แยกในการ์ด "งานที่ไม่นับรวม") |
| 2 | ชื่อรุ่นมี `AIRPODS` | Airpods |
| 3 | ชื่อรุ่นมี `IPAD` | iPad |
| 4 | ชื่อรุ่นมี `WATCH` | Watch |
| 5 | ชื่อรุ่นมี `MAC` หรือ `STUDIO` | CPU |
| 6 | ชื่อรุ่นมี `IPHONE` หรือบริบทมี `BATTERY`/`DISPLAY` | มี BATTERY → iPhone Battery · มี DISPLAY → iPhone Display · ไม่งั้น iPhone Other |
| 7 | ไม่เข้าข้อไหนเลย | ACC |

**งานที่ถูกตัดออกจากยอด** — Service Non-Repair และงานที่ `Repair Status` เป็น
`Declined - Repair Cancelled` แต่ยังนับจำนวนแยกไว้ให้เห็นในการ์ด 🚫 งานที่ไม่นับรวม

## 📊 หน้าตาที่ได้

แบ่งเป็น 3 แท็บ — **สรุป · ภาพรวม · รายละเอียด**

### แท็บ "สรุป" — หน้าแรกที่เปิดมาเจอ

(โผล่เมื่อใส่ชีตงานซ่อมแล้ว) เห็นทั้งสองฝั่งพร้อมกันในหน้าเดียว

| | |
|---|---|
| **การ์ด 2 ใบเคียงกัน** | 💰 ยอดขาย (บาท) · 🔧 งานซ่อม (รายการ) — แต่ละใบมีตัวเลขเดือนนี้ คาดการณ์สิ้นเดือน และ ▲▼ เทียบเดือนก่อน/ปีก่อน |
| **ช่องวันตัดยอดแยกกัน** | แต่ละการ์ดมีช่อง "ถึงวันที่" ของตัวเอง เพราะสองชีตอัปเดตถึงคนละวันได้ |
| **ประโยคสรุป** | รวบทั้งสองฝั่งเป็นบรรทัดเดียว |
| **บล็อกรายละเอียด 2 ชุด** | ใต้ประโยคสรุป — การ์ดย่อย (หมวดที่ดัน/ฉุดยอด · สะสมทั้งปี · ปริมาณงาน หรือ งานที่ไม่นับรวม) และแถบรายหมวดเรียงมาก→น้อย ของทั้งยอดขายและงานซ่อม |

เดือนที่เลือกใช้ร่วมกันทั้งสองการ์ด · ฝั่งไหนยังไม่มีข้อมูลเดือนนั้นจะขึ้นว่า "ยังไม่มีข้อมูล"

### แท็บ "ภาพรวม" — สำหรับผู้บริหาร

อ่านจากบนลงล่างได้เลย แต่ละชั้นตอบคนละคำถาม:

| ชั้น | ตอบคำถาม | สิ่งที่เห็น |
|---|---|---|
| **ตัวเลขใหญ่** | เดือนนี้ได้เท่าไหร่? | ยอดรวมตัวโต + ป้าย ▲▼ เทียบเดือนก่อนและปีก่อน + เส้นแนวโน้ม 12 เดือน |
| **ประโยคสรุป** | แล้วไง? | สรุปเป็นภาษาคนให้อ่านจบใน 2 บรรทัด พร้อมบอกหมวดที่ดัน/ฉุดยอด |
| **การ์ด 4 ใบ** | อะไรทำให้เปลี่ยน? | หมวดที่ดันยอด · หมวดที่ฉุดยอด · ยอดสะสมทั้งปี · ปริมาณงาน |
| **แถบรายหมวด** | เงินมาจากไหน? | เรียงจากมากไปน้อย เห็นสัดส่วนเป็นแถบ + % เทียบเดือนก่อน |
| **สินค้าขายดี** | ตัวไหนขายดี? | 8 อันดับแรก พร้อมหมวด จำนวนชิ้น สัดส่วน และเทียบเดือนก่อนรายตัว |
| **แนวโน้มทั้งปี** | เทรนด์เป็นยังไง? | กราฟ 12 เดือน ปีนี้ vs ปีก่อน · ชี้ที่แท่งเห็น %YoY |

หมวด/สินค้าที่**เดือนก่อนไม่มีขายเลย** จะขึ้นว่า `ใหม่` แทนที่จะเป็น `—`
ส่วนหมวดที่ยอดเป็น 0 จะจางลงเพื่อไม่ให้แย่งสายตา

> **หมายเหตุเรื่อง "หมวดที่ดัน/ฉุดยอด":** วัดด้วย **จำนวนเงินที่เปลี่ยนไป** ไม่ใช่ %
> เพราะหมวดเล็กที่โต 300% อาจกระทบยอดรวมน้อยกว่าหมวดใหญ่ที่โตแค่ 5%

### ไอคอนประจำหมวด

ทุกที่ที่มีชื่อหมวดจะมีไอคอนนำหน้า ช่วยให้กวาดตาหาได้เร็วกว่าอ่านชื่อ:

| | | | | | | | | |
|---|---|---|---|---|---|---|---|---|
| 🛡️ AC+ | 🎧 ACC | 💻 CPU | 🔄 Exchange | ✨ Film | 🔋 iPhone Battery | 📱 iPhone Display | 👑 Privilege Member | 🔧 Service Bill |

แก้ได้ที่ `const CAT_EMOJI` ในไฟล์

### แท็บ "รายละเอียด"

| ส่วน | เนื้อหา |
|---|---|
| **กราฟเทียบรายหมวด** | ปีก่อน · เดือนก่อน · เดือนนี้ ยืนเทียบกัน 9 หมวด |
| **ตารางรายหมวด** | เรียงตามยอด มี 🥇🥈🥉 ให้ 3 อันดับแรก · ติดป้าย **🏆 แชมป์** ให้หมวดที่เพิ่มเป็นเงินมากสุด และ **⚠️ ต้องดู** ให้หมวดที่ลดมากสุด · หมวดที่ยอดเป็น 0 จะจางลง |
| **สินค้าทั้งหมด** | มีปุ่มกรองตามหมวดด้านบน · แต่ละแถวรวมชื่อ หมวด และสัดส่วนไว้ในช่องเดียว มีแถบยาว-สั้นบอกยอด และ 🥇🥈🥉 ให้ 3 อันดับแรก |
| **ประวัติรายเดือน** | ทุกเดือนของปีที่เลือก × 9 หมวด + เทียบปีก่อน |

**ปุ่มกรองหมวดในตารางสินค้า** — กดแล้วเหลือเฉพาะหมวดนั้น พร้อมยอดรวมของหมวดที่ท้ายตาราง
ตัวเลขบนปุ่มคือจำนวนรายการ เช่น `🔄 Exchange 22` · ตัวกรองติดค้างเวลาเปลี่ยนเดือนด้วย
(ถ้าเดือนใหม่ไม่มีหมวดนั้นเลย จะกลับไปเป็น "ทั้งหมด" ให้เอง)

### อื่นๆ

**ดาวน์โหลด CSV** ได้ทั้งสรุปรายหมวดและรายการสินค้าทั้งหมดของเดือนนั้น (แนบคอลัมน์ต้นทาง
`Category (Name)` / `Sub Category` มาด้วย ไว้ตรวจว่าถูกจัดหมวดถูกไหม)

**ลิงก์ "ตรวจสุขภาพข้อมูล"** ท้ายหน้า — บอกว่าอ่านได้กี่เดือน แต่ละเดือนมาจากแท็บไหน กี่รายการ
ยอดเท่าไหร่ และมีอะไรผิดปกติไหม

รองรับ **โหมดมืด** (ปุ่ม ◐ มุมขวาบน) และ **จอมือถือ** — แถบรายหมวดกับรายการสินค้าย่อคอลัมน์เอง

## 🛡️ กันข้อมูลเพี้ยน

**ปัญหา:** ถ้าขอแท็บที่ยังไม่มี (เช่น `เดือน 7` ที่ยังไม่ได้สร้าง) Google **ส่งข้อมูลของแท็บแรก
กลับมาเงียบๆ** แทนที่จะแจ้ง error — ถ้าไม่ดักไว้ ยอดเดือน 1 จะไปโผล่ซ้ำเป็นเดือน 7

**วิธีดัก:** ระบบเทียบลายนิ้วมือ (hash) ของทุกแท็บ
- เนื้อหาตรงกับแท็บแรก → ถือว่าเดือนนั้นยังไม่มี ข้ามเงียบๆ
- เนื้อหาซ้ำกับแท็บอื่นในไฟล์เดียวกัน → ข้าม + เตือน
- เนื้อหาซ้ำข้ามไฟล์ (เช่น copy แท็บ ธ.ค. ปีเก่ามาเป็นเดือน 1 ปีใหม่แล้วลืมแทนที่) → เตือนพร้อมบอกว่าซ้ำกับเดือนไหน
- แท็บที่มีแต่หัวคอลัมน์ → เตือนว่าว่าง

## ⚠️ ข้อจำกัด

1. **ไม่มี RR คาดการณ์สิ้นเดือน** — คอลัมน์ `Doc Date` ใน Sheet ว่างทุกแถว ระบบจึงไม่รู้ว่า
   ข้อมูลนับถึงวันที่เท่าไหร่ คำนวณ Run Rate ไม่ได้ · ถ้าอยากได้ ต้องมีวันที่ในข้อมูล
   หรือกำหนดวันตัดยอดเข้ามาเอง
2. **ยังไม่รองรับงานซ่อม GSX** — โครงสร้างโค้ดเผื่อไว้แล้ว เพิ่มทีหลังได้
3. **ไม่มีการเทียบช่วงวัน (1-15 vs 1-15)** — เหตุผลเดียวกับข้อ 1
4. **หมวดที่ไม่มียอดจะแสดงเป็น 0 แบบจางๆ ท้ายรายการ** — ไม่ซ่อน เพื่อให้เห็นว่ามีหมวดนั้นอยู่
5. **ความเร็วต่างกันตามทางที่เปิด** — บน Worker โหลด ~0.3 วิ (เซิร์ฟเวอร์ดึงให้แล้ว cache ไว้
   10 นาที) · บน GitHub Pages ~8-12 วิ เพราะเบราว์เซอร์ต้องยิงไป Google เอง 24 ครั้ง
   กด Refresh บังคับดึงใหม่ข้าม cache เสมอ · ตั้งรีเฟรชอัตโนมัติทุก 15 นาที
   ปรับได้ที่ `SETTINGS.AUTO_REFRESH_MIN`
6. **ค่าที่ตั้งไว้ผูกกับเบราว์เซอร์** — เปลี่ยนเครื่องหรือล้างข้อมูลเบราว์เซอร์ต้องกรอกใหม่
